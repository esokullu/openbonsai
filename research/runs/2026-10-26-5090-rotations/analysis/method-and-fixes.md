# Paired 16×8 method and implementation record

This is a completed bounded research comparison of unrotated and Hadamard-rotated ternary reconstruction, starting each condition from the same original official Qwen/Qwen3.5-9B BF16 checkpoint (`c202236235762e1c871ad0ccb60c8ee5ba337b9a`). Both conditions finished training, diagnostic evaluation, export and independent fresh reload. It is not a Bonsai reproduction or a lossless-compression claim. The predeclared scope excludes RCO allocation/search, endpoint training, a candidate grid, 128-sample fitting, and a full benchmark. Upstream's vendored RCO code being present does not mean RCO was exercised here.

**Matched recipe.** Both conditions use the same 200 conservative decoder projections, group size 128, rank-64 correction, sigmoid factor mapping, Huber loss with delta 1, factor LR 0.005, LoRA LR 0.001, AdamW with zero weight decay and clipping threshold 1, linearly decayed learning rates, seed 5090, and gradient checkpointing. Embeddings, output head, vision, small recurrent gates, convolutions and norms remain original. MLP `gate_proj` is among the quantized projections; it is not included in the retained recurrent-gate category. Sixteen fixed calibration traces are truncated/padded to 512 tokens; batch, window and stride are all 1; eight epochs give 128 updates per window and 4,096 total. Each window has 102 soft and 26 hard updates; the last actual soft sharpness is 29.8828125.

The rotated condition uses deterministic full-name-derived signs, sign seed 5090, normalized Hadamard blocks of width 4096, and unchanged native coordinate ordering. In row-vector notation, `R = D H`; input and source-weight rows become `xR` and `WR`. The effective quantization-domain weight is `WR + B A / 64` (or `W + B A / 64` without rotation). Group means/MAD and mapped factors remain differentiable through this effective weight. Hard forward uses ternary weights; hard backward uses the frozen Jacobian at the **last actual soft forward's pre-update parameters and sharpness**, including A/B. The original-teacher bypass uses unmodified W and ignores the correction. Floating BF16 rotation has measured rounding differences; teacher bypass is tested separately for exactness.

The consumed calibration hash is `09df0a26800a20e46288b5a775075c91dc5c0e98bc0bf81ac7906f304a0d820f`: 5,330 source tokens, 5,234 active tokens, 2,958 padding positions, and 96 truncated tokens across three records. Evaluation uses the frozen diagnostic hash `330ffeeb77fa384492a6494e1e698edd400d7088456dbd0b7bc0fd366b7d838a`: 2,048 scored NLL tokens, 20 ARC-Easy questions and four fixed generation prompts, greedy/nonthinking, no KV cache, maximum 128 new tokens. These repeatedly used diagnostics are development data, not fresh final confirmation.

**Source integration and preserved fixes.** The new checkout is pinned to `ff5bbf10e94d5d35282b9dfa48fa13069289fbfd`; earlier run directories remain immutable. The corrected rank-64 quantizer memory port was integrated with the new upstream rotation API rather than replacing it with the earlier factor-only implementation. Source snapshots, patches and per-file hashes were recorded before execution. The final runtime-integrated archive hash recorded in `runtime-source-freeze.json` is `ba4d28808cf1f7244e0ac9244eb4d0d6a4ce683b90f1f13741dc9caf0a0af87f`; this note reads that recorded digest without rehashing the archive.

- Source weights transfer once with `copy_weight=False`; replacement discovers paths without retaining duplicate modules. Rotation happens inside complete-row FP32 chunks, followed by the row slice of `B @ A / rank`, then statistics and quantization. Row counts align to `group_size/gcd(group_size,input_width)`; valid-element masks exclude final padding. Native widths 4096/12288 align with group 128. The nominal scratch target is 8 Mi elements; unusual dimensions can require a larger indivisible aligned span. No persistent full rotated-weight copy is kept.
- Factors, A/B, statistics and compact saved soft states remain FP32 under BF16 model casts. Chunked checkpoint recomputation preserves snapshot semantics and all input/factor/A/B gradients. Source-dtype reconstructed outputs still exist, with a transient concatenation copy; the implementation bounds FP32 intermediates rather than claiming zero full-weight reconstruction.
- Window caches are temporary and cleaned after each window. Losses mask padding; hybrid attention masks/rotary arguments and nested checkpoint behavior are preserved. Optional audits measure actual optimizer deltas, gradients, moments, snapshots, phase timing/memory and boundary statistics without changing the objective or schedule.
- The mixed-export plan fingerprints original BF16 weights **before** replacement. Selected original tensors are omitted before retained-tensor CPU transfer. Export streams bounded payload slices, avoids redundant CPU/storage copies, and clones only required aliases. Reload creates meta parameters with initialized native buffers, then transfers owned payloads. Explicit rotation signs and row indexes are included in complete-file codec size comparisons: BITCOS is selected only when smaller than 2-bit, with 2-bit winning ties. Learned codes/scales are preserved; legacy rotated export remains rejected.
- All tokenizer assets and an operational `generation_config.json` travel with each artifact. The pinned repository had no separate official generation-config file; the saved config is constructed from the model config with the explicit model/tokenizer EOS union `[248044,248046]`. This preserves the experiment's stopping settings rather than inventing new defaults. Offline tokenizer/template loading, multiple-EOS stopping, and independent-process reloads are tested.

**Runtime-cache amendment.** Before either matched training or quality result, measured repeated decoding projected roughly three hours per capped packed diagnostic evaluation. A documented amendment enables one decoded BF16 cache per immutable projection while preserving the same 64-row `F.linear` calls, rotations, bias handling and concatenation. Row 512 was rejected because CUDA outputs differed despite identical decoded weights. The selected cache adds 13,824,425,984 bytes (12.875 GiB) of runtime weight storage, is nonpersistent, and is absent from serialized candidate payloads. Artifacts record the policy; the loader supports a cold override and otherwise restores it. Cold load, cache preparation, full 513-token memory warmup and steady evaluation are measured separately. Both allocated and reserved cached-inference memory must stay below 28 GiB; failure stops execution. This trades VRAM for less decoding and makes no low-bit-kernel or speedup-over-BF16 claim.

**Preflight evidence.** The final integrated CPU suite passed 639 tests, with two skips solely for unavailable Windows symlink privileges. Independent dense-equation and explicit Hadamard tests cover BF16/FP32, exp/sigmoid, soft/hard, rank 64, row/group crossings, final padding, input/all parameter gradients, FP32 preservation and nested checkpoints. CUDA gates passed both actual projection shapes `(12288,4096)` and `(4096,12288)`, positive-progress floating rotation placement, a native hybrid 16×8 fixture for each condition, exact teacher bypass, tokenizer preservation and independent reloads. Separate fresh real-9B resource preflights retained all 32 layers/200 source storages while fitting only the first four layers for one epoch; each checked all 64 updates and restored the complete layer list. They were resource checks, with no saved learned state or quality claim. Cache gates then showed exact cold/warm decoded weights and outputs at sequence lengths 512/17/1, exact native-model logits, immutable payloads, and fresh-process policy restoration plus actual stopping at both EOS choices. `launch-gate.json` records the passed gate and unchanged training implementation after those checks.

**Historical comparisons and interpretation limits.** The earlier corrected run at `0cbf667…` used rank 64 but only 16×1, exp mapping, MSE and factor LR 0.001: 12 soft/4 hard steps per window, last soft sharpness 28.125. Its proposed 16×8 and 128-sample successors were explicitly stopped before launch. It is therefore not the matched control for rotation; comparisons with it combine budget, mapping, objective and LR changes. The original pilot predates that corrected rank-64/snapshot integration. Prior least-squares recovery artifacts likewise are not inputs to this pair.

Local hard-MSE improvements measure reconstruction conditional on already-quantized prefixes; they do not demonstrate end-to-end fidelity, and Huber step losses are a separate quantity. Both 4,096-update audits pass and all 32 local hard MSEs improve in each condition. Rotation improves the saved hidden probe at every layer, but the final relative RMSE remains 1.0710 (unrotated 1.0907). Packed diagnostic NLL is 9.25535 versus 14.43711 and ARC is 8/20 versus 1/20. These numerical results do not establish useful generation. Both fresh reloads match their packed-runtime references exactly; poor hard-FP32 behavior predates serialization. Full paired measurements and limits are in `final-training-findings.md` and `distribution-comparison.md`. Retained endpoints alone cost about 4.07 GB, so this configuration also cannot approach a 2 GB total artifact.

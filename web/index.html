Open research in ternary compression.

An open framework that compresses a dense language model, or your own fine-tune of one, to ternary weights in the Bonsai format. Qwen3.5-9B becomes a 2 GB file that runs in Prism's llama.cpp.

How it works

Four stages turn a BF16 model into ternary weights, then one export writes Prism's PTQ1_0 GGUF.

  1. Rotate. A signed Hadamard rotation in Prism's layout spreads large weights across each block, so three levels fit them better.
  2. Round. Sequential GPTQ rounds every large linear layer, the embedding and head included, to −1, 0 or +1 with one scale per 128 weights, on calibration data that includes the model's own answers.
  3. Refine. ScaleQ/CAT-Q refinement. Research only for now: it has not yet beaten GPTQ plus distillation, so the default pipeline skips it.
  4. Distill. The codes stay fixed while every scale is trained against the original model's predictions. On Qwen3.5-9B this closes more than half of the gap to the original on our small dev suite (dev NLL 3.48 → 2.89; original 2.42).

Measured end to end on Qwen3.5-9B with the research scripts the package ports, and reproduced by the package's own end-to-end run. Other dense models have an adapter, tested only on tiny random models so far, with no real-model results yet. Math, code and non-English output are the main weakness: on small GSM8K and HumanEval subsets the from-scratch model scores 30/100 and 6/50, against 77/100 and 45/50 for Prism's Ternary Bonsai 2 9B. Recalibrating on the model's own math and code answers is the next step.
